# FF Arena — required-test manifest (GAP-10)
#
# Format (one entry per line, `#` starts a comment):
#
#   <ID> | <phpunit --filter value> | <spec row / source> | <why it is required> [| max_skips=N (justification)]
#
# `max_skips` is only for a test class that deliberately covers two dialects: it
# then necessarily skips the half that does not apply to the profile being run.
# The budget is a maximum, not a licence — a NEW skip beyond it still fails the
# gate — and the justification must name the dialect. Every other entry has an
# implicit budget of zero.
#
# The filter value is passed to `php vendor/bin/phpunit --filter <value>`, so it
# may name a class (`Tests\Feature\Finance\AtomicSettlementTest`) or a single
# test method. The runner (tools/run_required_tests.py) fails the build when a
# required entry:
#
#   * matches no test at all (the test was deleted or renamed — the guard rotted),
#   * is skipped, incomplete or risky (a green run must mean the path really ran),
#   * fails or errors.
#
# tests/Static/test_gap10_identity_floor.py asserts every ID below exists in the
# repository with the same name, so an entry cannot silently disappear.
#
# Row references point at docs/required-tests/TRACKER_143_REVIEW.csv and
# docs/FF-ARENA-FINAL-MASTER-GAP-MATRIX.md as quoted by first.md. Those two
# files are NOT part of this repository snapshot (see
# docs/GAP-10-FINDINGS-REGISTER.md, finding F-01); the row numbers below are
# therefore carried from the specification and are the authoritative link.

# A1 — production guard on the numbered simulation families
# ---------------------------------------------------------------------------
# The finding: with APP_ENV=production, POST /v1/gameberry/core/feature-192/play
# returned 200 and mutated the caller's gold wallet, while final9 was refused —
# the guard only matched `gameberry/final…`. Two controls are asserted, because
# either alone is a single point of failure: the route files are not registered
# outside local/testing (checked in a subprocess, since a booted process cannot
# un-register a route), and the middleware refuses every mutating request under
# a numbered family with 403 regardless of the route table.

GAP10-A1-001 | Tests\Feature\Gameberry\NumberedSimulationProductionGuardTest | A1 production guard | In production the numbered route files are not registered even when the feature flag is on (verified by booting a second process), the reported core and final9 writes are refused with 403, and no gold or gem transaction is written; in testing the same call succeeds and settles exactly one gold bet, so the refusal is policy rather than a broken URI.

# A2 — the virtual-wallet row lock (the `$this->lockForUpdate()` no-op)
# ---------------------------------------------------------------------------
# `$this->lockForUpdate()` on a model instance returns a query builder and
# executes zero queries, so concurrent spends could double-spend gold and gems.
# The pgsql entry proves the lock with two real connections; the SQLite-safe
# entry proves the SQL the model actually issues, so the regression is caught
# even on a profile that cannot model a second writer.

GAP10-A2-001 | Tests\Feature\Postgres\VirtualWalletLockTest | A2 row lock | Two real PostgreSQL connections: the second writer blocks on FOR UPDATE until the first commits, and the final balance is correct — the locked row is the one that is read and written.
GAP10-A2-002 | Tests\Feature\Gameberry\VirtualWalletLockQueryTest | A2 lock SQL | The spend/add paths issue a locking SELECT (captured SQL / toRawSql on the pgsql grammar) rather than a no-op builder call, so a regression is caught on every dialect.
GAP10-A2-003 | Tests\Feature\Concurrency\SlotClaimSerialisationTest | A2 lock family (F-39) | A writer that waits on the parent-row lock cannot claim a slot, promote a waitlisted team or add a roster member that another transaction has already taken. Deterministic on the PostgreSQL profile (a forked child is guaranteed to be blocked); the three services assert their own refusal.
